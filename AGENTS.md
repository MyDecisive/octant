# Repository Guidelines

## Project Overview

Octant is a Go 1.25.9 Connect-RPC (connectrpc) service developed by MyDecisive that acts as an AI DevOps visual control plane for the SmartHub telemetry platform — optimizing a system before incidents occur. It provides guided UI workflows, Connect RPC APIs, SmartHub installation orchestration, Argo CD and Datadog integrations, connection creation and manifest generation, Data Fidelity Validation workflows, runtime setting updates, and Clarity views over the telemetry stream (health, cost, and volume data).

Module: `github.com/mydecisive/octant`. It is a single-process Kubernetes-native server: `cmd/octant/main.go` builds a `go.uber.org/dig` dependency-injection container, then `Start` serves one Connect-RPC mux. Octant is modeled as co-located with SmartHub in the same Kubernetes cluster, reading in-cluster Prometheus, GreptimeDB, and Valkey-backed state.

## Architecture & Data Flow

Entry: `cmd/octant/main.go` calls `registry.Initialize()` (builds `dig.New(dig.DeferAcyclicVerification())` and `Provide()`s every service impl, binding concretes to interfaces via `dig.As`), `registry.SetupGracefulShutdown(container)`, then `container.Invoke(registry.Start)`.

`registry.Start` is build-tagged: `internal/registry/start.go` (`//go:build !webapp`) serves RPC only; `internal/registry/start_web.go` (`//go:build webapp`) additionally mounts the React SPA + Swagger. Both call `rpc.Server.Handler()` and `http.ListenAndServe` on `config.Port`. The Connect mux (`internal/rpc/server.go`) wires grpcreflect (dev), grpchealth, 8 Connect service handlers (ArgoCD/Install/Datadog/Connection/Setting + budget Filter/Timeframe/Budget), wraps in h2c HTTP/2, adds validate + otelconnect interceptors and rs/cors CORS.

Data flow: Connect handlers (thin proto↔domain adapters) → service layer (connection/integration/setting/manifest/budget/metrics) → K8s stores (mdai-data-core ConfigMap/Secret controllers, installlog CRD) + ArgoCD API + Prometheus + GreptimeDB + MDAI gateway.

Persistence is Kubernetes-native: connections live in the `mdai-octant-connections` ConfigMap, integrations in `mdai-*` Secrets, and install progress in the `OctantInstallLog` CRD (group `octant.mydecisive.ai`, Namespaced). ArgoCD drives cluster deploys; Prometheus validates telemetry flow/fidelity; GreptimeDB (MySQL protocol) + MDAI gateway feed budget metrics/filters. Install events are ordered (action/result/timestamp/namespace/ref/subtype/message).

## Key Directories

- `cmd/octant/` — entry point (`main.go`).
- `internal/registry/` — dig DI wiring (`dig.go`), build-tagged `Start` (`start.go`, `start_web.go`), graceful shutdown.
- `internal/config/` — `Configuration` loaded via cleanenv (env vars + optional `OCTANT_CONFIG_PATH` YAML); `Environment` enum via enumer.
- `internal/rpc/` — Connect-RPC server and mux wiring (`server.go`).
- `internal/rpc/handler/` — 8 Connect handlers, one per service.
- `internal/connection/` — `Connection[T]` CRUD over the ConfigMap store + ArgoCD deploy orchestration.
- `internal/connection/manifest/` — manifest generation: `//go:embed` YAML templates, renderer, generator, zip compressor; `manifest/data/` has enums (App: MDAI/CERT/CONNECTION/VALIDATOR; OutputFormat; DestinationType) and the DataMapper.
- `internal/integration/` — Datadog + ArgoCD integration stores backed by Secrets (`Integration[T]`).
- `internal/argocd/` — ArgoCD API client (`argo-cd/v3` apiclient): `APIClient`.
- `internal/installlog/` — `OctantInstallLog` CRD store (`InstallLogStore`).
- `internal/metrics/` — Prometheus client factory + connection status via PromQL.
- `internal/setting/` — runtime setting manager + builder (per-connection mutex).
- `internal/budget/` — budget metrics; `data/db/` GreptimeDB builder, `data/` retriever + MDAI gateway accessor, `filter/` setting controller.
- `internal/wrapper/` — `HTTPClient` wrapper over `http.Client`.
- `internal/mock/` — mockery-generated mocks (one `mocks.go` per source package).
- `internal/test/` — test helpers (`NewTestLogger`, `ValidateOutput`).
- `api/v1/` — CRD Go types (`install_log_types.go`) + autogenerated deepcopy.
- `web/` — webapp-tagged embedded UI (`web.go`) + `swagger.yaml`.
- `deployment/` — Helm chart (Chart.yaml, values.yaml, templates/, crds/).
- `config/` — kubebuilder CRD + RBAC kustomize (default/ bundles rbac + crd).
- `kubernetes/appsv1/` — empty directory; real k8s API comes from `k8s.io/client-go` + mdai-data-core stores.

## Development Commands

Requires Go 1.25.9 (`GOTOOLCHAIN=go1.25.9` pinned in Makefile). All `make` build/test targets run `go mod tidy` first.

- API-only build: `go build -trimpath -ldflags="-w -s" -o octant ./cmd/octant`
- Webapp build: `make build` (`go build -trimpath -tags webapp -ldflags="-w -s" -o octant ./cmd/octant`). Requires UI `dist` copied into `web/dist` (from the separate `octant-ui` repo).
- Run: `./octant` — port `5678` (override `OCTANT_PORT`).
- Test: `make test` (`go test -count=1 ./...`), `make testv` (verbose), `make cover`, `make coverhtml`.
- Lint: golangci-lint v2.11.4 using `.golangci.yml`; CI runs `make tidy-check` + golangci-lint.
- Docker: `make docker-build` / `docker-push` (buildx multi-platform, distroless static final image).
- Install tools: `make install-tools` (mockery v3.7.0, enumer, jet, golangci-lint v2.11.4, controller-gen v0.21.0, kustomize v5.8.1, helmify v0.4.20).
- Regenerate: `make generate` (DeepCopy), `make manifests` (CRD + RBAC), `make helmify`, `make mockery`.

## Code Conventions & Common Patterns

- Each package defines its own interface; concrete impls are bound to interfaces with `dig.As` in `internal/registry/dig.go`. Handlers and consumers receive interfaces, never concretes.
- Logging: `go.uber.org/zap` global logger everywhere. `zap.Any` is forbidden (define a `MarshalLogObject`); no `fmt.Print`/`log.Fatal`/`os.Exit` in committed code (forbidigo).
- Enums via `enumer` (e.g. `environment_enumer.go`), with generated `*_enumer.go` files.
- JSON field tags are snake_case; YAML/XML/TOML are camelCase; env vars upperSnake (tagliatelle).
- Go 1.25 idiom: tests use `t.Context()` (never `context.Background()`).
- Error handling: return errors to `main`; RPC handlers map errors to Connect error codes.
- CRD types + generated deepcopy live in `api/v1/`; controller-gen regenerates via `make generate`.

## Runtime/Tooling Preferences

- Go 1.25.9; `GOTOOLCHAIN=go1.25.9`; `CGO_ENABLED=0`. Go modules only — no Node in this repo (the UI is the separate `octant-ui` repo, its `dist` is copied into `web/dist`).

## Testing & QA

- Frameworks: `stretchr/testify` (`assert`/`require`/`mock`), `DATA-DOG/go-sqlmock`, mockery-generated mocks in `internal/mock/` (template `testify`, packages `<srcpkg>mock`), `go-faker/faker/v4`, `zaptest`, k8s fake clients, `httptest` TLS + connect client, real gRPC server for ArgoCD integration.
- Common patterns: table-driven `t.Run` subtests with `t.Parallel()`; mock setup `mockXxx.EXPECT().Method(mock.Anything, mock.MatchedBy(...), ...).Return(...).Once()` (`.Times(n)` for repeats, `.Run(...)` for streams); `require.NoError` + `assert.Equal`; error matching via `require.ErrorContains` / `assert.ErrorIs`; Connect errors via `require.ErrorAs` + `connectErr.Code()`.
- Mock regeneration: `make mockery` from `internal/mock/mockery.yml` (lists ~20 interfaces; `mock.go` holds the `//go:generate` line).
- Test helpers: `internal/test` (`NewTestLogger`, `ValidateOutput`); local `newTestManager(t, ...)` with `t.Helper()` building fixtures from faker + zaptest.
- Naming: `Test<Subject>_<Method>`; subtests lowercase descriptive phrases; mocks `Mock<Interface>` + `NewMock<Interface>(t)`.
- Coverage: codecov patch target 80%; CI runs `CGO_ENABLED=0 go test -cover -coverprofile=coverage.txt -v -count=1 ./...`.
- Untested packages: `internal/config/` and `api/v1/` have no test files.
